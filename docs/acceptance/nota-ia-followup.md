## 验收边界与重跑

`npm run test:journeys` 启动独立本地 Vite 服务和临时目录中的真实 HTTP 曲谱库，使用 Playwright Chromium / WebKit 操作正式 App 的可见入口、CodeMirror、实际排版和实际本地 OMR。最终断言取自同一 App 当前文档、公开曲谱库 API 与下载文件。没有替换编辑器、转换或识别引擎。

保存故障在 HTTP 边界注入，409/404 用临时库的真实并发更新和删除产生；联网来源采用固定 HTTP 返回，以隔离外部网络。它们验证客户端旅程，不证明线上馆藏新增或外部服务可用。文件选择的空结果通过浏览器文件输入注入，不能当成 iPhone 原生相册取消操作通过。

- 默认命令：`npm run test:journeys`（Chromium 桌面）。
- 手机配置命令：`NOTA_BROWSER=webkit NOTA_DEVICE=iphone npm run test:journeys`。采用 iPhone 13 的浏览器参数、390×844 CSS 视口与触控；主要保存 / 返回 / 管理确认用真实触摸事件。可选 `NOTA_BROWSER=chromium` 或 `webkit`，`NOTA_DEVICE=iphone` 或省略；这些参数没有启动真实 iPhone。
- 默认监听隔离端口 5192，可用 `NOTA_JOURNEY_TEST_PORT` 指定其他端口；端口占用时拒绝启动，不访问已部署服务。临时库与每次独立的 Vite 依赖缓存结束即删除，多个工作区不会竞争共享 `node_modules/.vite`。
- 证据：忽略的 `local/qa/spec9-journeys/`，包含逐旅程截图、`report.json`、真实图片输入和识别观察。WebKit 手机配置另存 `webkit-iphone/`，报告记录真实引擎版本、参数、基线及是否过滤执行。原图、曲谱正文、下载成品不随 Git 上传。
- 定向调试可设 `NOTA_JOURNEY_FILTER` 为场景名片段；零匹配以非零状态退出。报告明确记录 filter、Git 基线、工作区是否改动、引擎版本、注册 / 执行数及 `full` / `partial` / `no-match` / `incomplete` 范围；定向通过不能代替整套通过。
- 原专业功能可用 `npm run test:editor` 重跑；其可选私有项目输入与限制见对应脚本及 Dolce 对照记录。

## 本轮发现并修复

每项先用上述真实 App 旅程复现失败，再最小修复并复跑：

1. 详情页隐藏专业状态栏，保存失败仅写该栏，用户看不到原因。改为用原有对话框显示具体保存错误；失败仍保留编辑和替换保护，关闭后可重试。
2. OMR 的 `hasInputs` 按上游设计包含失败待重试输入。详情原图身份提示改为检查当前附属识别项目，不把失败输入说成当前稿已附带原图；没有删除原引擎保留失败输入供重试的语义。
3. 详情页拖入图片识别失败同样只写隐藏的专业状态栏。非首页失败用原有模态显示具体错误和重新选图入口；首页保持原错误和重试，不增加全局消息系统。
4. 简谱识别返回零音符时仍 emit 空头并替换旧稿。落地前检查实际识别结果含音符（含休止符），无内容走已有事务回滚并提供双语错误。没有调整 OCR 几何、模型或音符判定算法。
