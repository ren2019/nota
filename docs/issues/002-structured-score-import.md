# NOTA-002：联网寻找结构化曲谱并验证后导入——研究与隔离 spike

状态：用户已批准，最小方案已接入产品并部署；未覆盖范围见接入记录。

## 问题

能否由 agent 联网寻找儿歌、国歌等曲谱，优先使用 ABC、MusicXML、LilyPond 等结构化数据，核对后生成可入库候选，减少图片识谱错误？

## 本次问题与验证边界

- 调研开源/开放谱库，分别确认作品、具体编配和数字文件许可，不以“国歌/儿歌”直接推定无版权。
- 实际获取代表性文件；验证标题版本、格式、八度、节奏、小节与反复等。
- 区分格式往返一致、外部参照一致与人工确认，避免 agent 自己生成再自己判正确。
- 输出 dry-run 候选与来源清单，不写入现有曲库、不部署。

产物：`docs/spikes/002-structured-score-import.md`、`local/spikes/002-structured-score-import/`。

## 完成条件

主来源证据、实际样本结果、坏数据拦截、可运行流程与 MVP 推荐明确；停在评审。

## 验证结果

见 [完整报告](../spikes/002-structured-score-import.md)。MIT、Gutenberg、OpenScore 三份实际样本共 87 小节，限定范围的独立音高/时值对照通过；四种故意错误均拦截。已有可审批的 dry-run 候选，未入库。LilyPond 转换、原生 MusicXML 浏览器端到端及同音起音/复杂结构尚未验收。
