# 通过独立工具向运行实例提交曲谱

2026-10-28，用户确认首版面向熟人圈子，所有 agent 连接同一个 Nota 实例。提供 skill 和可独立安装的 CLI，复用运行实例的曲谱库 HTTP 接口，使日常新建和修改曲谱无需打开项目工作区或重新发布应用；MCP 留待出现明确需要时再增加。

获授权的 agent 可直接新建或更新曲谱，保存后在曲谱库中可见，不增加网页待审流程。并发修改必须报告冲突，不静默覆盖。首版从 agent 已准备好的可编辑谱文开始，图片识谱和链接找谱可由其他能力完成。该路径沿用现有单实例共享模型，不另建曲谱库或账户体系。

核心检查由运行中的 Nota 服务执行，CLI 获取检查报告并提交保存，复用同一套解析规则。首次接入需部署新增能力，日常新增和修改曲谱不需要重新发布应用。agent 负责取得最新版、编辑、处理检查结果和核对改动、按版本保存并回读，返回改动摘要及曲谱链接。检查通过且没有未解决疑点时直接保存；遇到影响正确性的歧义，向人提出具体问题，不为通过检查擅自改变音乐内容。

人最终在曲谱库中试听验收；试听不作为本次提交流程的硬 gate，不增加待审状态。保存后发现问题，可继续交由 agent 修正。没有可信原谱时，检查只能证明谱文及改动符合已执行的检查，不能声称与原稿一致。

每位使用者配置独立、可撤销的工具访问凭据，首次配置后日常使用无需手动网页登录，不增加 Nota 账号体系；机器访问的具体实现仍需适配部署入口。按曲名查找有多个结果时，先列出候选供人选定；新增时发现同名，先确认修改已有曲谱还是新增另一版本。确定目标后按曲谱唯一编号操作。

删除采用可恢复的软删：保留曲谱完整内容，从正常曲谱库隐藏，并提供可再次找到的恢复入口；网页和 CLI 使用相同的删除、恢复规则。修改直接更新，不保留历史版本；误改由 agent 再次修正。恢复只能找回删除时的版本，不提供修改回滚能力。

采用运行实例接口而非仓库文件提交，使曲谱维护与应用发布分离；相应地，工具需要适配实例访问控制，不能将 HTTP 保存成功视为曲谱内容已经校对正确。本决定不表示 CLI 已实现或远程提交已实测通过。

执行规格和后续状态以 [GitHub #23](https://github.com/ren2019/nota/issues/23) 为准。用户已确认以独立安装的 CLI 连接真实服务和存储、回读并在网页使用的主要验收链路；人的最终试听不作为硬 gate。

用户追加指定在本机使用 Codex 作为验收 agent，skill 通过 SkillFlow 安装并部署到 Codex，CLI 使用实际交付件安装验证。实测曲谱为《Five Little Ducks》（首句“Five little ducks went swimming one day”），实施时记录旋律版本与来源；这些是后续验收要求，不表示安装或实测已经完成。
