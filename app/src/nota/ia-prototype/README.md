设计问题：如何优先完成制谱打印，其次支持手机陪练，并保留偶尔深度编辑的能力？

用户优先级：**制谱打印 > 手机陪练 >> 深度编辑**。
状态：用户倾向 B，继续迭代曲子详情内的编辑 / 练习双态；布局尚待反馈。只迭代原型，不实施正式页面。
关联：https://github.com/ren2019/nota/issues/6

## 本轮：B 默认练习，复用 Dolce 原有面板

最新确认：谱库打开曲子默认进入练习；练习 tab 在左，编辑在右。
手机编辑态主要入口只保留 **调式 / 导出 / 编辑**。

- 移除 B 上一轮自制的「校对」「改谱」工具与确认流程。
- 「编辑」实际复用 `editor/visual/menu.ts::buildPalette` 与 `keys.ts::VISUAL_ACTIONS`，保留原面板的动作、分组、符号和编辑 / 插入模式可用状态。
- 未往原面板加入 Nota 新增的两种转换与目标基准控件；新增调式在外层独立入口。
- 原版自带的移调、调号等动作仍来自 Dolce 动作表，不删除、不替换成 Nota 转换。
- 面板容器继续支持原图对照和源码入口；原有面板按钮适配触控大小。
- 练习态：只读谱面与固定播放 / 阅读控制；两态保留同一份内存演示稿。
- 桌面工具在右侧，手机在底部展开。手机可预览 360 / 390 / 430 CSS 像素容器。

原型运行仍只连接桩 runner：模式切换和入口可操作，不执行实际改音、转换、识别、音频、保存、下载或上传。

运行：根目录 `npm run prototype:ia`。
默认练习：`http://localhost:5188/?variant=B&phone=1&width=390`。
指定编辑态：`scene=review`；指定练习态：`scene=practice`；桌面自适应：`phone=0`。
从谱库点开任一演示曲子也默认练习。新带入曲谱仍进入编辑，便于制作。
底部方向键切换 A/B/C；输入框不拦截方向键，Escape 收起工具。

## 隔离与验证

专用 Vite 配置不加载曲谱库/API 中间件。正式启动入口要求 `import.meta.env.DEV` 与 variant 参数才导入原型；正式构建会移除原型导入。
独立入口 `standalone.ts` 可通过 esbuild 打包，将生成的 CSS / JS 内联为单文件 HTML，默认打开 B。

- `npm run build`：TypeScript + Vite 通过；保留上游既有分包警告。
- 原生 Edge：从谱库打开默认练习、练习在左编辑在右、编辑底部三入口、Dolce 原面板展开和编辑 / 插入状态已实际操作；此前已验证调式演示、阅读设置与固定播放栏。
- 360 / 390 / 430 容器目视检查；桌面右侧面板检查。
- 原型不替代真实 iPhone / Android PWA 的触控、软键盘、音频、安全区及分享 / 打印验收；issue UI #22 仍待设备验收。
