# Nota IA 探索原型

设计问题：如何优先完成制谱打印，其次支持手机陪练，并保留偶尔深度编辑的能力？

用户优先级：**制谱打印 > 手机陪练 >> 深度编辑**。
状态：用户倾向 B，继续迭代曲子详情内的编辑 / 练习双态；布局尚待反馈。只迭代原型，不实施正式页面。
关联：https://github.com/ren2019/nota/issues/6

## 本轮补充：曲谱管理与保存后练习

- L1 的 N 从横移 4 单位改为 2 单位，向左微调，保持音符一线一间。
- 练习态顶部直接显示「导出」，不再把导出 / 设置藏在更多菜单里。播放和阅读设置只保留底部入口。
- 编辑态顶部改为「保存入库」；模拟成功后保留当前谱面与调式，切换到左侧练习态并收起弹窗。
- 两态顶部均保留「…」，只收纳曲谱管理：重命名、从库中删除。重命名同步当前标题与内存列表；删除需在原型内确认，然后返回列表。数据仅在内存中，刷新恢复，未调用正式服务。
- 360px 容器检查顶部动作并列；继续沿用紧凑调式 / 导出弹窗与独立 Dolce 页面。

## 上轮补充：L1 位置、体验文案、源稿入口

- 用户偏好 L1：N 下移并水平居中，左音符头在线（y=52）、右音符头在线间（y=48），相差半格；细斜线保留。
- 页头「体验示例」改为「体验」。
- 上轮将源稿下载放到顶部过于突出，且「源稿」易被理解成图片。顶部现在只保留「存曲谱库」。
- `.123` 是可重新导入编辑的乐谱文本文件，不是 PNG 图片。入口收回「导出 → 其他导出格式」，命名「可编辑乐谱（.123）」，旁边说明可重新导入继续编辑。
- PDF / 打印与 PNG 图片仍为主要导出入口。下载与入库依旧只模拟。

Dolce 独立页通过隔离文档承载原壳 `dolce-shell.html` 和 `styles.css?inline`，原布局的源码 / 谱面、工具栏、记号面板与断点保持。
仅接入占位源码、占位谱面和演示 runner；不是完整编辑引擎接入，不实际改音、转换、保存、下载或播放。原图也仍为演示占位。
独立页没有新增 Nota 调式面板。浏览器返回恢复原型详情与内存稿；Logo 选择可返回首页看小尺寸。

运行：根目录 `npm run prototype:ia`。
默认练习：`http://localhost:5188/?variant=B&phone=1&width=390`。
编辑态：`scene=review`；首次制谱：首页 `scene=new`。
Logo 比较：`view=logos`（建议 `phone=0` 并排比较）。
独立编辑页：`view=editor`；宽窄只触发 Dolce 原断点。

单文件制品打包：在 `app/` 执行 `npm exec vite -- build --config vite.ia-artifact.config.ts`，将 `out/ia-artifact/prototype.js` 与 `dolce.css` 内联到 HTML。独立页引用的原壳和样式也已内嵌，无需联网加载 Dolce。

## 隔离与验证

专用 Vite 配置不加载曲谱库/API 中间件。正式启动入口要求 `import.meta.env.DEV` 与 variant 参数才导入原型；正式构建会移除原型导入。
独立入口 `standalone.ts` 通过专用 Vite 制品配置打包，默认 B 练习态；原壳和样式作为原文内嵌。

- `npm run build`：TypeScript + Vite 通过；保留上游既有分包警告。
- 原生 Edge：360px 单行页头、390px 紧凑调式 / 导出弹窗、独立 Dolce 页在宽屏源码 / 谱面并排和窄屏原断点、浏览器返回、Logo 对照已操作并目视检查。此前的练习默认入口与底部播放栏保留。
- 360 / 390 / 430 容器目视检查；桌面右侧面板检查。
- 原型不替代真实 iPhone / Android PWA 的触控、软键盘、音频、安全区及分享 / 打印验收；issue UI #22 仍待设备验收。
